# Bullfrog Courier materials

The production Courier uses the approved Bullfrog hull and separate top/bottom turret drawings. Five stored regions supply eight explicit bearings through horizontal reflection. All visible albedo RGB and every alpha sample are unchanged from `docs/art/bullfrog-sprites-v1/`; no ImageGen, resampling or repainting was used in material preparation. Original PNG byte streams are preserved in `raw/bullfrog/`. Production PNGs clear only invisible RGB beneath alpha=0 and use lossless PNG compression to reduce pack size. The replaced, unreferenced Courier hull files are archived locally under `raw/bullfrog/previous-courier-hull/`.

`scripts/prepare-bullfrog-materials.py` produces the PNGs, source sidecars and canonical materials here, with the full originals, maps and sidecars in `raw/bullfrog/`. Raw files are local editable sources, excluded from ordinary builds and Git by the existing repository policy. `geometry-registration.json` in that raw directory records the component volumes and source-space registration. Re-run the script explicitly when recalibrating art; builds consume the tracked outputs.

Depth is linear camera-facing displacement, white nearer, centred at 0.5 with frame-specific calibration. It is a registered geometric approximation: a yawed hull volume, separate engine casings and recessed aft nozzle planes. Neither paint colour, glow, ink darkness nor baked shadows are inputs to depth. Normals are computed from continuous geometric Z gradients before 8-bit depth quantisation; +X is right, +Y up, +Z toward the viewer. These are geometric proxies, not a recovered exact mesh. Covered hull/turret surfaces absent from the source drawings remain absent.

Hull frame height is 1280 and rendered scale is 25, preserving the previous Courier's 15/768 metres per source pixel. Each turret has a 256-pixel frame and `scale_permille: 1000`, so its original pixels align with the hull's mount coordinates. The bottom artwork is already inverted and uses `flip_y: false`. Root depth offsets compensate the actual quantised hull depth sample to place the two centreline mounts at their geometric depths, independently of signed draw-order hints. Turret muzzle markers follow the visible barrel ends, with inferred projections where a stern view hides the muzzle.

Small legacy sensor, beam and PDC visuals have distinct registered auxiliary sockets, rather than being stacked on the two large kinetic turret mounts. They retain their mechanisms and firing rules. Mission-instance art overrides now inherit the same Courier material and registration.

Three exhaust markers describe port, starboard and the higher central stern nozzle. They use the existing aggregate drive's thrust for presentation; no simulation engines were added. The drive, steering, impulse, collision and all non-presentation System fields are unchanged. Source coordinates are retained when mirroring, and port/starboard engine labels swap on reflected frames.

`verification.json` records source byte identity in raw, exact visible RGB/alpha identity in production, the unchanged simulation contract and per-view marker calibration. For the manually invoked production rendering exercise, build `phoenix_bullfrog_gallery` and run it with a verified base pack. It captures eight bearings, normal/depth diagnostics, 90-degree turret traverse and powered exhausts; it is not a CTest or balance assertion.
