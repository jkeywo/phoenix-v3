# Console and Controller definitions

Read compiler.cppm and types.cppm first.

Console ownership/profile declarations, command sections, actions, candidates and bridge settings.

Dependencies: Foundation commands, generic state trees, knowledge and explicit catalogue compiler collaborators.

Ownership: ControllerTreeBindings is compiled setup data. Its immutable policy artifacts retain actions, candidates and objective bindings compiled against that policy's registry. The catalogue compiler uses the retained tree program to check policy restrictions. World binds fitted endpoints and creates each Controller's continuation separately.

WidgetReadoutBinding also belongs to the definition contracts. The widget compiler validates source fields against portable presentation encoders and telemetry IDs, and compiles permitted-board pointers. Prepared Catalog values retain these accessors in `widget_readouts` and the corresponding presentation declarations in `widget_data`. Equipment-scoped visual meters compile into the same readout path as named data. Authored packs and restricted Console exports retain the original scope declarations. Optional permitted values may remain unavailable without invalidating a supported binding.

Validation: Controller runtime, handover, content and knowledge integration cases. These are existing integration surfaces; this guide does not claim they have run for a particular revision.
