# Workshop foundation

The Map panel's **Skybox** picker selects a 2:1 panoramic PNG from the current pack
or its dependencies. **None** clears it; new maps start with None. Import a suitable
PNG through the normal image import flow to add a choice. Save/reopen and both
package encodings preserve the choice. Existing base and training maps explicitly
select the Settled Dark panorama supplied by the base pack.

Play the map to view its skybox. It follows camera direction at infinite distance,
behind ships, navigation effects and nebula fog; translating the camera does not
move it. The top-down editing grid and individual material previews remain unchanged.

Use **File > Package…** to package a game pack or selected scenario directly as source ZIP or compiled DAT. See [packaging and loading assets](asset-loading.md) for dependencies, client Console bundles and loading backgrounds.

Run `native.exe --workshop`, or launch `?type=workshop` from the browser build. The same C++ editor runs on both platforms. Native uses Windows file dialogs. Browsers with File System Access use open/save pickers and retain a file handle for saving in place during the editing session. Other browsers download a copy and explicitly report that limitation; they cannot overwrite a previously downloaded file. Browser saves never rely on temporary WASM filesystem writes.

1. Workshop starts with an editable **Phoenix Base Game** (`phoenix-base`) pack. Use **Add map** above the map to add a scenario directly to this pack; **Editing pack** identifies the destination. Set its **Map name**, author the map, then **Save pack**. **File > New pack** starts a separate mod with the base game as a dependency. In **Definitions**, set the mod's unique pack ID and apply it. A draft can be incomplete; verification/save names missing or incompatible fields.
2. Select a definition, use **Template ID > Rename template** to rename it (all map instances, ship-slot choices and child templates update), and set an optional **Display name**. In **Properties > Appearance and physics**, edit its camera-facing/eight-direction images, render scale, **Collision type** (Circle or Oriented box), dimensions and mass. **Systems and ownership** selects fitted Systems and edits their engine/steering/radar and other capabilities. The remaining Properties sections expose resources, assembly placements, knowledge feeds and Console Controllers/complexity profiles. Mass zero means static scenery. The simulation loads these verified definitions when starting a game.
3. Double-click the map to place the selected definition. Click an instance to select it, drag to move it, and edit its heading/position numerically. **Entities** supplies duplicate/delete. Middle-drag pans and the wheel zooms. On touchscreens, drag one finger to pan and pinch two fingers to zoom around their moving midpoint. These gestures also work in the GM inspection map, and touch map drags do not place or move authored entities. The map shows first-image thumbnails and heading markers; this is not the final 3D billboard renderer.
4. **Scenario > Inspect ship slots** opens named spawn transforms in Properties. Pick the allowed ships; verification requires each choice to have an engine, steering and positive mass.
5. **Consoles** creates and selects reusable console definitions; their fields and preview appear in the shared **Properties** inspector. **Console ID > Rename console** changes a definition and repairs legacy ship, explicit Station and inherited Console references; runtime Console-seat IDs stay unchanged. **Display name** supplies a readable list label. Add radar/throttle/heading/status widgets, edit labels and the bounded 1000-by-1000 layout, and use the live RmlUi preview. Its radar contacts and operating values are isolated sample data; preview controls cannot issue gameplay commands. The same Console renderer and headless presentation model serve play and preview. Assign an authored console in the entity properties.
6. **File > Save** (`Ctrl+S`) saves the whole verified pack, including every map, Console, template and imported asset. The default base game opens from the installed pack library: **Save** replaces that pack immediately without asking for a location, and its updated scenarios are available in New Game. Native saves it in the user library; browser saves persist in the menu's IndexedDB storage. Reopening Workshop loads those edits. An opened file saves back to the same location; a new pack asks for a location on its first save. **Save as...** (`Ctrl+Shift+S`) chooses a separate file and remembers that destination for subsequent saves. Cancellation or failure preserves the previous destination. **Save map / Save map as...** separately save a map JSON and remember that map's location; a map JSON alone does not contain templates or assets. Use the map dropdown to switch among maps. To play an externally saved pack, import its ZIP through Mod Packs and select it in place of the earlier version.

To author a mod, first give it its own pack ID. **Load dependency pack** imports a base pack (then further dependencies in order). Select a dependency entity to create a derived entity, then flatten it to edit resolved fields. Alternatively, **Override dependency definitions** copies a selected entity, map, Console or state tree into the editable pack and declares that exact ID in the override manifest. An existing local copy is preserved. Verification still rejects conflicting, unresolved or unused overrides. Export includes the mod and dependency manifest; select the base before the mod when loading. When reopening a dependent mod, load its dependencies first.

`native.exe --workshop-pack path/to/pack.zip` opens a standalone pack directly. Adding `--smoke` takes a six-frame capture and exits. A refused map/pack load preserves the current document. Loaded inherited definitions are flattened for editing; the general loader still supports inheritance.

Static tool labels use the shared translation resources, with stable ImGui identities across pseudo-localisation. English and pseudo-localisation are the current tool language baseline; ImGui does not provide the player's HarfBuzz shaping and full bidirectional editing. Additional tool languages need their own validation before being declared supported. GM mode keeps world mutation disabled: remote GM clients require host approval, while the trusted local host can inspect directly, including in a reserved display region. See [MVP status](mvp-status.md) for acceptance limits.

Workshop-wide **Edit > Undo/Redo** covers authored data, assets and dependencies, with Ctrl+Z / Ctrl+Y (also Ctrl+Shift+Z). **Verify** checks the whole draft. Separate **State trees**, **Scenario** and **Test** areas handle graph navigation, map/scenario selection and disposable execution; their authoring fields use Properties. See [gameplay authoring](gameplay-workshop.md).

## Comic materials and lighting

Import the albedo/normal/depth PNGs with **Import PNG**, select a reusable definition, then **Import sprite sidecar...** in Properties. Matching imported/dependency filenames are selected automatically; resolve any missing or ambiguous mapping, including the radar PNG, then apply the material. Sidecars carry `billboard_mode` (`camera` or `eight`), `render_scale`, emissive state, calibrated frames/attachments, and `files.radar_icon`. Older sidecars infer direction mode from one/eight frames and default to scale 1. The import controls show the selected direction mode and scale before applying; mismatched frame counts are refused without changing the current sprites. **Import as engine effect** attaches a matching directional thrust material instead. The importer consumes the supported sidecar data; ordinary pack loading uses the canonical schema-3 material, not files outside the pack.

Properties exposes atlas rectangles, pivots, camera bearings, depth span/centre, emissive state, attachment coordinates, signed layers and nozzle depth offsets. Normal/depth textures are optional. Engine settings expose plume scale, light intensity and range. Invalid drafts are retained for correction; preview/export reports verification errors rather than replacing a working pack.

**Radar icon PNG** selects any imported PNG or a dependency asset. The base game supplies editable ship, asteroid, sun and contact PNGs under `assets/radar/`. Icons keep a readable screen size and rotate with the entity heading; heading zero points right. Workshop/GM maps and native/browser crew radars render these sprite assets. Legacy vector-symbol packs remain readable.

The **Lighting and sprite preview** tab uses the production renderer. Select a definition for an isolated preview or enable **Preview whole map** to include placed entities and first allowed ships at their slots. Bearing, elevation, distance and preview thrust are isolated authoring values, not gameplay commands. Scene lighting edits the map's sun direction/colour, ambient fill, hatching and shadow settings. Comic, smooth, unlit, normals, depth and sun-visibility views help calibrate maps. Preview images regenerate on changes; the runtime colour pass still draws directly into the Viewscreen viewport.

For the packaged example, load the base ZIP as a dependency and open the separate training ZIP, select `training.lighting` in the Map tab, open the preview and enable **Preview whole map**. Compare zero and full forward thrust: the asteroid behind the Courier receives orange illumination while the forward hull stays shaded. There is no added engine halo. Export/reload retains materials, depth calibration, attachments and lighting. Explosion events are supported internally but have no authoring or gameplay trigger yet.

**Console Controllers and complexity** defines decision ownership. Add Controllers, select their trees and command channels, bind physical consumers, and assign each Controller to human or AI operation in each Console profile. The same Controllers run when the entity is unclaimed or fully AI-operated. Physical Systems retain factual reporters. See [Controller authoring](controller-content.md).

Each material frame offers **Mirror horizontally**, including frames inside named entries. The live preview reflects its maps, pivot and engine markers together. Source coordinates remain editable as drawn. Save/export/reload and crew asset transfer preserve the flag. See the [five-region, eight-bearing example](content-format.md#sprite-region-mirroring).

## Inspector consolidation � 19 October 2026

Workshop now routes entity, Console, scenario, ship-slot and state-tree authoring through one Properties inspector. State-tree graphs, scenario navigation and disposable Test retain separate areas. The former Gameplay authoring window and its independent selection/history/Verify controls are removed. Shared snapshots include metadata, assets and dependencies; unchanged resources are shared so large packs retain useful undo history. Console preview uses canonical sample System bindings without rewriting authored widget targets, and reports preview errors without terminating Workshop.
