# Workshop foundation

Run `native.exe --workshop`, or launch `?type=workshop` from the browser build. The same C++ editor runs on both platforms. Native uses Windows file dialogs; browser builds use file selection and downloads. Browser exports are real downloaded files, not temporary in-memory saves.

1. In **Definitions**, set a unique pack ID and apply it. Import a PNG, then create an entity definition. A draft can be incomplete; verification/export names missing or incompatible fields.
2. Select a definition and edit its camera-facing/eight-direction images, render scale, engine/steering/radar capabilities and circle/box dimensions/mass in **Properties**. Mass zero means static scenery. The simulation loads these verified definitions when starting a game.
3. Double-click the map to place the selected definition. Click an instance to select it, drag to move it, and edit its heading/position numerically. **Entities** supplies duplicate/delete. Middle-drag pans and the wheel zooms. The map shows first-image thumbnails and heading markers; this is not the final 3D billboard renderer.
4. **Ship slots** adds named spawn transforms. Pick the allowed ships; verification requires each choice to have an engine, steering and positive mass.
5. **Consoles** creates reusable console definitions. Add radar/throttle/heading/status widgets, edit labels and the bounded 1000-by-1000 layout, and use the live RmlUi preview. Its radar contacts and operating values are isolated sample data; preview controls cannot issue gameplay commands. The same Console renderer and headless presentation model serve play and preview. Assign an authored console in the entity properties.
6. **File** creates/selects maps, loads/saves map JSON, and exports/opens verified ZIP packs. Use the map dropdown to switch among maps in a pack. Map JSON references definitions supplied by the current pack/dependencies; ZIP export includes the pack's own definitions and imported assets.

To author a mod, first give it its own pack ID. **Load dependency pack** imports a base pack (then further dependencies in order). Select a dependency entity to create a derived entity, then flatten it to edit resolved fields. Alternatively, **Override dependency definitions** copies a selected entity, map, Console or state tree into the editable pack and declares that exact ID in the override manifest. An existing local copy is preserved. Verification still rejects conflicting, unresolved or unused overrides. Export includes the mod and dependency manifest; select the base before the mod when loading. When reopening a dependent mod, load its dependencies first.

`native.exe --workshop-pack path/to/pack.zip` opens a standalone pack directly. Adding `--smoke` takes a six-frame capture and exits. A refused map/pack load preserves the current document. Loaded inherited definitions are flattened for editing; the general loader still supports inheritance.

Static tool labels use the shared translation resources, with stable ImGui identities across pseudo-localisation. English and pseudo-localisation are the current tool language baseline; ImGui does not provide the player's HarfBuzz shaping and full bidirectional editing. Additional tool languages need their own validation before being declared supported. GM mode keeps world mutation disabled: remote GM clients require host approval, while the trusted local host can inspect directly, including in a reserved display region. See [MVP status](mvp-status.md) for acceptance limits.
