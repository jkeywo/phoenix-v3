# Lobby console board and QR invitation

20 October 2026. Linux/Xvfb and Chromium with software rendering; manually invoked smoke evidence.

The shared native/WASM lobby renders the selected ship's Consoles together as individual nine-slice cards. Each shows the authored name and description, occupant/readiness, complexity and permitted claims. The right column contains a GM card, other connected ships with occupied/total Console counts, and connected players waiting for a Console. There are no crew/Console/GM tabs, Console pages or scrolling lobby containers. The waiting-player section receives more space as its population increases.

`phoenix_lobby_smoke` loads the shipped Cruiser through the real offline lobby and menu renderer. Native captures cover 1280×720, 1100×720 and an 800×900 host region. The journey checks that all six Console cards appear together, claims a native Console, replaces it with GM, releases GM and reapplies the display layout, then replaces a GM role with a Console. It also checks the Settings return journey and that Console/profile/GM controls remain inside each viewport. The browser version passes the corresponding board/layout/Settings checks. These virtual display claims are not physical monitor acceptance.

A separate live Chromium journey hosts a Cruiser through the local signalling service. An actual mouse click on the QR opens its exact player invitation in a new tab. The host remains hidden while its shared worker session pump admits the player. The player appears in the host's waiting list, selects Helm and receives the Ready action without host approval. Captures also cover the existing landscape rotation and compact phone viewport behavior. Native captures are retained in ignored `build/linux/lobby-ui-smoke`; browser captures are in ignored `build/web/lobby-ui-smoke`.

After integrating `main` at `caeb2e1`, all 22 native CTests and 13 launcher cases pass. The real signalling-service pre-game integration case passes with automatic ship/player/GM invitation admission, late crew, competing claims, content verification, launch and recovery. It also checks that Console descriptions cross the lobby wire to a client. The complete native build and all three WASM role builds pass. The generated panel and nine-slice metadata load successfully in both renderers.

The synchronous browser smoke emits the existing `Cannot resume a closed AudioContext` exception after its captures and explicit window close. The live host/player journey does not close its audio runtime during the checks. Physical screen readers, touch hardware and six-monitor performance were not exercised.

Integration retained the existing per-tab browser profiles and acknowledged worker clock. The smoke waits for graphics preparation both at entry and after setup-changing claims. Console readouts include station names and descriptions for accessibility, and claim/profile action labels identify their Console. The native host retains its Viewscreen rather than silently claiming an operating Console on the primary screen.
