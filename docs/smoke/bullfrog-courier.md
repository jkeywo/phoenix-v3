# Bullfrog Courier art integration

30 October 2026. The new hull, separate top/bottom turret atlases and their geometric normal/depth maps replace the production Courier presentation. Editable source copies are saved locally in `raw/bullfrog/`; builds use `content/base/assets/bullfrog/`.

The bake uses alpha coverage and authored geometric registration, never albedo brightness or shadows. All three raw albedo files remain byte-identical to the extracted approved artwork. Production PNGs preserve every visible RGB and alpha sample; clearing only invisible RGB under alpha=0, and archiving the now-unreferenced previous hull outside the pack, reduces the shared source-pack size. Camera-facing Z is a geometric proxy rather than an exact recovered mesh; view-space normals derive from that continuous field. See the [material contract and calibration](../../content/base/assets/bullfrog/README.md).

Verification compared the old and new Courier drive, steering, impulse, collision and every non-presentation System field. They are unchanged. There is still one aggregate propulsion System; the three new exhaust sockets are visual. The existing production base and Test Missions packs were authored through the production packager, including mission-instance art inheritance.

The explicitly invoked `phoenix_bullfrog_gallery` loads the production pack, creates the actual Rescue Courier through `World`, obtains its production scene projection and renders it through `SceneRenderer`. Hidden-window native captures were inspected for all eight bearings, normal/depth diagnostics, 90-degree turret traverse and three-nozzle thrust. Local captures are `build/bullfrog-bearings.png`, `build/bullfrog-normals.png`, `build/bullfrog-depth.png`, `build/bullfrog-traverse.png` and `build/bullfrog-engines.png`. This is authored-content visual evidence, not a balance golden, physical-device test or browser screenshot.

The first default parallel MSBuild attempts stalled resolving project references without a compiler diagnostic. The current packager, verifier and gallery built successfully with one worker; the earlier packager executable also predated the current content schema. Local receipts are `build/bullfrog-build-single.log`, `build/bullfrog-gallery.log` and `build/bullfrog-production-packs.log`.

The subsequent whole-game rebuild was not completed: concurrent shared-workspace content edits first exceeded the previous pack budget, briefly produced incomplete JSON, and then referenced missing Comms portraits (`assets/personnel/rescue/military-idris-holt.png` and `military-chief-rao.png`). Those unrelated changes are excluded from this art commit. Earlier verified pack and gallery evidence above remains valid; it is not a claim that the final shared workspace build passed. The last attempted build log is `build/bullfrog-native-final.log`.

Reproduce the bake with `python scripts/prepare-bullfrog-materials.py`. Build the manual native target with `./scripts/build.ps1 -Target native -BuildTarget phoenix_bullfrog_gallery -Jobs 1`, then run `build/native/Release/phoenix_bullfrog_gallery.exe build/native/base.zip` from the repository root. Source colour pixels are preserved; surfaces hidden by the original painted turrets are not reconstructed, so independent traversal can reveal small mount gaps.
