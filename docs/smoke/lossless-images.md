# Lossless DAT image benchmark — 23 October 2026

Exact lossless WebP was selected for DAT image records after comparing the production PNG assets in Windows native Release and Emscripten Release running in Node/V8. Source PNG files remain unchanged. The previous raw-pixel DAT image decoder has been removed; generated DAT artifacts were upgraded, and unsupported image records are rejected with a rebuild message.

## Measurements

The corpus contains all 53 PNG files under `content/base/assets` at the time of the run, including colour, normal, depth, radar and presentation textures. Original PNGs total 30,518,244 bytes. Each alternative uses an independent ZIP entry; already compressed PNG/WebP data is stored. WebP includes its production 16-byte record header. Values below sum the entries rather than including a complete game manifest and definitions.

| Representation                               | Image-entry bytes | Native median decode | WASM median decode |
| -------------------------------------------- | ----------------: | -------------------: | -----------------: |
| Previous RGBA + ZIP level 1                  |        38,045,008 |            791.52 ms |        1,064.93 ms |
| RGBA + ZIP level 9                           |        34,142,682 |            744.53 ms |          719.32 ms |
| Optimised/original PNG, whichever is smaller |        29,663,671 |            666.73 ms |          528.52 ms |
| Exact lossless WebP                          |        21,050,646 |            580.18 ms |          587.38 ms |

WebP reduced the previous image-entry size by **44.7%**, and the optimised PNG alternative by **29.0%**. It was smaller for every image in this corpus; adaptive per-image PNG/WebP selection therefore produced the same size. The adaptive timing control measured 527.00 ms native / 533.05 ms WASM for the same payloads, illustrating scheduling/warm-up variation. These are three-pass observations on this workstation under other development activity, not fixed performance requirements or browser/GPU/device acceptance.

Timed intervals include archive extraction, decoding and RGBA allocation/copying. Disk reads and pixel comparison are outside the interval. Every RGBA byte and dimension matched on every native/WASM pass, including fully transparent pixels. High-effort WebP encoding took 223.05 seconds for the corpus in the initial encoding run, versus 1.72 seconds for level-1 RGBA, 8.21 seconds for level-9 RGBA and 15.09 seconds for PNG. The separate full WASM encoding pass took 168.68 seconds for WebP, 1.44 seconds for level-1 RGBA, 7.18 seconds for level-9 RGBA and 14.26 seconds for PNG. All 53 encoded WebP records and source pixel buffers matched native byte-for-byte (`encoding-identity.log`). These separately scheduled runs are not a claim that WASM encodes faster than native. This trades offline packaging work for smaller downloads. Production packaging caches byte-identical verified encodings within a 32 MiB bound to avoid repeated work across ship companions.

The complete newly exported production root DAT is **21,296,247 bytes**, including definitions and all assets. The packaging path decodes every newly encoded image and refuses export if any RGBA byte changes.

## Reproduction and receipts

Run `./tests/manual/image-codecs/run.ps1` after normal bootstrap/native configuration. See the [benchmark instructions](../../tests/manual/image-codecs/README.md) for codec parameters and measurement scope. The pinned libwebp 1.6.0 scalar encoder is shared with production. Lossless mode uses method 6, quality 100, `exact=1`, and no near-lossless preprocessing.

Ignored receipts are under `build/image-codec-bench/`: `native-final.json`, `web-final.json`, `corpus/manifest.json`, `corpus/encoding.json`, `corpus-web/encoding.json`, `encoding-identity.log`, `base-dat-export.log` and `upgraded-dats.json`. The upgrade pass checked 589 generated DAT files and converted 299 files containing 2,594 legacy image records, updating 17 menu sidecars. Only generated build artifacts were changed; source PNGs remain editable originals. Active native/browser companions are regenerated by the production C++ packager. Historical source snapshots were not edited.

## Integration verification

Native and WASM content integration checks, the native menu suite, the WASM root/migration verifier, all 27 launcher cases and all three real client transport journeys (valid, missing and corrupt DAT sidecars) pass. Native and WASM produced identical encoded fixture hashes. Synthetic DAT round trips include all alpha values, nonzero RGB under alpha=0, colour/data channels, editable PNG re-export, malformed dimensions/truncated bitstreams and explicit refusal of obsolete image records. Deployment validation now opens each published companion's image entries and requires the current `PHXWEBP1` record. Native/WASM encoded fixture identities are compared without a fixed golden hash.

The final artifact scan (`upgrade-verification.json`) checked **618 generated DAT files / 241 distinct archives / 4,105 image records**, with **zero obsolete image records**. The production deployment check also passed with its current-record requirement. Source code contains no legacy image decoder.
