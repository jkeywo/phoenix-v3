# Shared game packets and content transfer

`phoenix_wire` owns the C++ packet envelope, authenticated encoding and ordered archive transfer. Native and WASM compile the same code; JavaScript adapters carry opaque payloads and implement platform services only.

Schema-1 game packets bind session epoch, source route, recipient, type and object body. Signed packets use HMAC-SHA256 over the canonical envelope. The decoder verifies the established transport sender, intended recipient, expected epoch, bounded length/nesting and proof before exposing a body. It does not interpret a room code or valid proof as permission to operate a ship. Unsigned traffic is limited to hello/welcome/refusal negotiation; command and peer-log traffic require established keys. Session admission must assign capabilities and enforce claim generations/sequences separately. This module is not a complete game-session handshake yet.

Secrets/epochs use 32 cryptographic random bytes from Windows CNG or browser `crypto.getRandomValues`; there is no pseudorandom fallback. Synthetic packet checks include an independent Node-crypto HMAC result and refuse forged payloads, sender substitution, wrong epochs and unsigned commands.

A content offer lists the exact ordered pack IDs, SHA-256 hashes and original archive sizes. The source verifies production loading and dependency resolution before advertising. The receiver allows up to 32 packs, 32 MiB per archive and 64 MiB total, with 12 KiB binary chunks carried as canonical base64 inside authenticated packets. A bounded sliding window tracks outstanding requests and retries missing chunks. Aligned out-of-order chunks and identical repeats are supported; conflicting repeats, bad offsets/lengths, wrong identities and oversized offers are refused.

Received bytes are not readiness. Every complete archive must match its offered digest and manifest identity, then the entire ordered set must pass the production ZIP/JSON/PNG/dependency loader. Cached bytes are rehashed/reloaded before use; a bad digest triggers re-fetch. The current cache input is an in-memory map; persistent platform caching and application progress/readiness wiring remain pending.

The native/WASM synthetic system integration transfers actual independently authored fixture packs (including a dependent mod and incompressible multi-chunk test data), authenticates chunks through the shared packet codec, retries a stalled window, accepts reordering/idempotent duplicates, verifies final exact archives/catalogue, uses verified cache hits and refuses corrupt cache/oversized/conflicting input. No production ship tuning, performance goldens or per-function coverage targets are used.
